# 내일의 빵

매일 판매·생산·마감 재고·폐기·이월 가능 재고를 기록하고 다음 날 생산계획과 모델별 성과를 비교하는 단일 매장 운영 앱입니다. 한국 시간의 날짜를 사용합니다.

## 운영 흐름

1. 상품별 생산 단위와 최대 생산량 설정.
2. 오늘 실제 판매 및 재고를 저장. 모르는 재고 수량은 null로 유지.
3. 다음 날 예상 판매 P50과 생산 기준 P75, 재고·예약·생산 단위를 반영한 생산량 비교.
4. 권장 수량을 수정하고 예측·계획을 확정. 예측과 입력 조건은 이후 변경하지 않음.
5. 실제 기록이 들어오면 당시 저장한 예측과 비교. 기존 계획과 실제 생산량도 별도 표시.

## 모델 범위

- 실제 Extra Trees 200개, CatBoost, 스플라인 Ridge, 규모 정규화 CatBoost를 기존 독일 자료 설정으로 학습하고 숫자 모델로 내보냈습니다. 요일 기준을 포함한 5개 기초 예측기를 사용합니다.
- 최종 결합은 ET 0.2675427911011525 + 보정 앙상블 0.7324572088988475입니다.
- 앱의 앙상블 가중치는 동일한 정규화 P50/P75 핀볼 손실 + 0.01 정규화를 primal-dual 방법으로 최적화합니다. 과거 56일 중 매주 월요일 이전 자료만 가중치 학습에 사용하고, 상품별 유사 패턴 오차는 매일 보정합니다.
- ET는 앱 운영을 위해 이동 보정을 적용합니다. 원 연구의 고정 평가 구간 보정과 다릅니다. 따라서 이전 연구 성적의 그대로 재현이나 새 매장에서의 성능 보장을 주장하지 않습니다.
- 새 매장의 상품에 독일 SKU를 임의로 매핑하지 않습니다. 기존 연구 상품 one-hot은 모두 0이며, 국가·상품의 분포 차이는 실제 매장 데이터로 검증해야 합니다.
- 7일 미만은 요일 기준으로 대체하며 UI와 저장된 예측에 fallback으로 명시합니다. 보정에 쓸 데이터가 부족하면 보정하지 않습니다.
- 기초 모델 자체의 자동 재학습은 포함하지 않습니다. 입력된 매장 자료로 가중치와 잔차 보정이 갱신됩니다.
- 날씨·행사·메모는 기록용이고 현재 예측 변수에 넣지 않습니다.
- 품절이 기록된 날은 보정·정확도·모의 손실에서 제외합니다. 품절 미기록은 null로 유지하며 비교에 포함된 개수를 표시합니다.
- 예상 수요는 관측 판매량을 대리값으로 사용합니다. 모의 과다·부족이나 3:1 가중 손실은 실제 폐기 또는 금전 손실이 아닙니다.

## 보관과 구분

실제/예시 공간을 D1에서 분리하고, 예시 기록은 합성 자료임을 표시합니다. 앱을 다시 열어도 기록이 남습니다. CSV 가져오기는 미리보기·검증·저장을 구분하고 이미 있는 날짜/상품을 조용히 덮어쓰지 않습니다. 예측은 상품/날짜 고유키로 고정하고, 실제 기록이 입력된 계획은 수정하지 않습니다. 재고 수량 불일치는 숨기지 않고 차이를 표시합니다.

## 검증

- Python 원 예측과 이식된 예측 20건: 최대 차이 약 1.42e-14 (ET와 두 CatBoost는 0).
- 판매 파생 변수와 FFT 특성 비교, 가중치 최적화와 SciPy SLSQP 목적함수 비교.
- 배치·예약·재고·용량·정수 올림, 당일/미래 결과를 변경해도 기존 예측이 유지되는지 확인.
- 실제 API 핸들러를 SQLite 기반 D1 어댑터로 실행해 입력 → 예측 저장 → 다음 날 실적 → 비교, DB 재열기, 예시 격리, CSV, 잘못된 입력을 검증.
- 검증 파일: research/engine-verification.json, workflow-verification.json, api-verification.json.
- 이 턴에서는 브라우저 UI QA를 요청하지 않아 실행하지 않았습니다. WebMCP 도구는 기능 탐지 후 등록되며 지원 브라우저에서의 실행 검증은 미실시입니다.

## 소스와 실행

pnpm, Vinext/React, Cloudflare Workers/D1. 설치와 빌드는 Sites 프로젝트 스크립트를 따릅니다. 스키마 변경은 db/schema.ts와 Drizzle migration으로 관리하며 런타임에서 테이블을 만들지 않습니다.

research/export_models.py는 기존 analysis_cache를 --source-root로 받아 연구 모델을 다시 학습·내보내는 재현 도구입니다. 원자료 전체는 이 저장소에 포함하지 않습니다. 독일 학습 출처와 날짜·행 수·모델 해시는 research/model-provenance.json을 참조하세요.
